# 技術構成

更新日：2026-10-26。`package.json`、`package-lock.json`、画面・APIのimportと処理から記録しています。導入、実際の利用、外部接続の確認を区別します。最新のチェックリスト・URL取得の実装範囲はコードから確認したもので、変更後のブラウザ合格は別に記録します。

## 全体の流れ

```text
文字入力 / ブラウザの音声入力
  → 端末で即時解析・記録
  → localStorageの下書き
  → Cloudflare Workersの認証済みAPI
      ├ D1：ユーザー別の状態スナップショット
      ├ R2：ユーザー別の添付
      ├ Workers AI：文章から商品・数量・分類を整理（初版で本番接続確認済み）
      ├ transcribe：明示的に送った録音・音声ファイルをWhisperで日本語へ変換
      └ link-preview：指定通販サイトのHTMLからページタイトルを取得
```

AIや通信の完了を入力の前提にしません。既存のローカルノートは自動取得しておらず、明示的な取り込み・書き出しでつなぎます。

主リストは直接チェックと解除を中心にし、価格・在庫等の細部は商品詳細、総額・予算・会計前確認・最近10件の操作は「その他」へ配置しています。会計前確認はかごの商品があるときに開けます。並べ替えは商品詳細の上下ボタンで行い、ドラッグの実装はありません。お気に入りと買い足し候補の行には個別の追加操作を残しています。

## サーバーと保存

### 食材照合

単位と保管場所は`app/components/storage-picker.tsx`の共有コンポーネントで扱います。HTML標準のselect/optgroupと、その他を選んだ時だけ出る入力欄を使い、独自メニューや依存パッケージを追加しません。値は従来どおり文字列で保存し、g/L等の選択肢ラベルと保存値を分けます。保存済みの独自値と空欄を保持するため、スキーマ移行は不要です。

`app/components/food-panel.tsx`で現在量の更新・購入追加・材料の確認を行い、`lib/client-food.ts`の通常のTypeScript関数で分数、人数、単位、在庫、未購入予定を計算します。正確な数量の差し引きにLLMや新しいAPIは使わず、通信・AI応答による数量の変動を避けます。既存のReact、CSS、localStorage、D1を再利用し、依存パッケージ・秘密設定・権限は追加していません。

同じ食材の現在量を登録した場合は既存在庫を更新し、購入履歴を再加算しません。未登録・量不明・単位不一致は確認を求め、g/kg・ml/Lだけを次元が一致する換算として扱います。購入予定分は手持ちとは別に数え、不足分の再追加を防ぎます。材料を表示しただけで在庫を消費する処理はありません。レシピURLの自動取得はまだ行わず、材料欄の入力と本人提供のグラタンの確認済み例を入口にします。

状態JSONはv3へ移行し、`inventoryOnly`（在庫専用の記録）、`stockKnown`（量の確認有無）、`inventorySource`、`stockReconciledQuantity`（現在量に含めた購入分）、`mealRecipe`と`cookingHistory`を保持します。v1/v2は読取時に移行し、PUTはv3のみ受け付けます。旧クライアントが新しいフィールドを落として保存する要求はHTTP 426で拒否します。D1は既存JSONスナップショットを利用するため、新しいテーブルや本番マイグレーションは不要です。

調理の控除は`lib/client-cooking.ts`の通常のTypeScriptで計算し、LLMは使いません。確認できる使用量だけを在庫から引き、手持ち→予備の順に控除します。料理の材料は合算して同じ在庫を重ねて引かず、量不明・未登録・不足・単位不一致は理由を残します。購入予定を消費せず、購入履歴も変更しません。

調理IDと各在庫の変更前後を最大50件の記録へ残し、在庫と同じスナップショットで同期します。同一IDの再実行を無視し、画面の連打防止と再読込後の反映済み表示を併用します。最新の調理の取り消しは、対象在庫と購入情報が反映後から変わっていない場合に限り、在庫の対象項目だけを戻します。別商品の追加や購入履歴・添付を巻き戻しません。既存の購入包含数量を更新して、過去の購入チェックを戻しても使用済み材料を再加算しないようにします。新しい依存・秘密設定・権限は不要です。

## AIと音声入力

文章の商品整理に使うWorkers AIモデルは`@cf/meta/llama-3.1-8b-instruct`です。商品名・数量・単位・分類をJSONへ整理し、結果の形・数量・文字数・分類を検証します。入力文はデータとして渡し、文中の命令をアプリの指示へ昇格させません。音声文字起こしは後述のWhisperモデルで分けて処理します。

`AI` bindingがあれば`env.AI.run`、なければ`CLOUDFLARE_ACCOUNT_ID`と`CLOUDFLARE_AI_TOKEN`を使うHTTP REST APIを呼びます。SecretはWorker側だけで読みます。12秒で待機を打ち切り、未設定・通信失敗・形式不正の場合は通常の文字解析へ戻します。[Cloudflare公式のREST API手順](https://developers.cloudflare.com/workers-ai/get-started/rest-api/)

本人の明示承認を受け、Workers AIの読み取り権限に限定したAPIトークンを作成し、Sitesの秘密設定へ接続情報を登録済みです。直接REST APIでHTTP 200・成功応答を確認し、「牛乳2本、卵1パック」の商品・数量解析が成功しています。公開済みアプリの設定画面には「AI接続を確認」ボタンを追加済みで、実Chromeで「Workers AIの応答を確認しました」の成功表示を確認しています。これは文章整理モデルの接続確認で、今回の音声文字起こしや、あらゆる自然文の解析精度を合格にするものではありません。任意の購入先が`store: null`で返る場合は未指定として省略し、数量・分類などの検証は厳密なまま維持しています。トークン値やアカウント識別子は本資料・ソースへ記載しません。文章整理へ送るのは操作時の入力メモで、既存ノート全体を自動取得・送信しません。音声の送信は下記の明示操作だけで行います。

### ブラウザの音声認識

`app/components/quick-composer.tsx`が入力・案内を担当し、`lib/client-speech.ts`がWeb Speech APIの`SpeechRecognition`または`webkitSpeechRecognition`のライフサイクルを管理します。`start()`を呼んだだけでは聞き取り中にせず、`starting`と`onstart`後の`listening`を分離します。開始待ちは15秒、停止要求後の終了待ちは3秒、聞き取り開始後のwatchdogは60秒です。

ネイティブの`not-allowed`、`service-not-allowed`、`network`、`audio-capture`、`no-speech`、日本語未対応等を区別して案内します。途中の認識は別表示し、確定結果のindexを記録して同じfinalの二重追記を防ぎます。確定文は既存の下書きへ追記し、「追加」で商品へ登録します。ブラウザ側の認識の処理主体・通信利用はその実装に依存します。

### 録音・ファイルからCloudflareで文字起こし

iPhone・iPadのChrome（CriOS）の通常の識別情報を検出した場合は、マイクボタンから録音・Whisper方式へ直接進みます。Web Speech APIの失敗待ちを挟みません。録音をCloudflareで文字にすることを入力欄の下へ事前表示し、OSとサイトのマイク許可は必要なままです。iPhoneの設定は「設定」→「アプリ」→「Chrome」→「マイク」を確認します。[Google公式の設定案内](https://support.google.com/chrome/answer/2693767?hl=ja&co=GENIE.Platform%3DiOS)。端末の識別情報が変わる場合は検出できないことがあり、案内内の録音ボタンも残しています。

ブラウザの音声認識が使えない場合は、本人が案内内の「録音して文字にする」を選ぶ代替経路を用意しています。`getUserMedia`・`MediaRecorder`・`Blob`を使う最大45秒の録音、またはWAV・M4A・MP3・WebM・OGGのファイル選択に対応します。上限は8MiBで、HTTPS等の安全なブラウザ環境と、サイト・OSのマイク許可が必要です。権限拒否を迂回せず、録音・ファイルをCloudflareへ送信することを画面に表示します。

ブラウザは音声バイナリをraw bodyとして`POST /api/transcribe`へ送ります。`lib/server-transcribe.ts`は認証ID・同一Originの確認後、Content-Type・実際の音声ヘッダー・容量を検証し、Workers AIの`@cf/openai/whisper-large-v3-turbo`へ日本語指定で渡します。既存の`AI` bindingまたはWorkers AI秘密設定を再利用し、新しいトークンや権限範囲は追加していません。アップロード読み取り15秒、AI待機30秒、ブラウザのHTTP待機40秒に制限し、空の音声・不正な応答・タイムアウトをエラーとして案内します。

キャンセル、scope変更による入力部の再作成、unmount、背景化で古いcallbackを無効化し、HTTPを中断してマイクのtrackを解放します。失敗した音声Blobは画面メモリだけに残し、接続復旧後などに明示的に再試行できます。文字起こしAPIは音声・文字起こし全文をD1・R2・アプリログへ保存せず、結果の文字だけを返します。成功した文字は通常の下書きに追記され、商品へ追加した結果は既存の保存・同期対象です。外部の音声処理サービスの保持方針全般を保証する記述ではありません。

今回の修正を含む単体テスト69 / 69、ローカルAPI30 / 30、型検査・対象ファイルのESLint・ビルドが合格しています。本番Chromeでは、Macの音声合成で生成した非個人情報の人工音声ファイル「牛乳を2本、卵を1パック」を選択し、WAV（95,934 bytes）とM4A（27,301 bytes）の両方でWhisperの文字起こしに成功しました。下書きの「牛乳を2本、卵を1パック。」を確認し、先に入力したメモへ追記して保持する操作も成功しています。

偽のWAVは本番でHTTP 415となり、日本語のエラー案内と再試行UIを表示し、既存の下書きを変更しないことを確認しました。ローカルブラウザでは開始待ちから15秒後の案内も確認しています。これらはファイル認識経路・入力保全・エラー処理の結果であり、実マイクの許可と発話、MediaRecorderでの本人の録音、本人スマートフォンでの実利用は未確認です。模擬イベント・単体テスト・人工音声ファイルの成功を、本人の聞き取り・録音の実利用合格へ置き換えません。

## 商品URLからのタイトル取得

`parseQuickText`はURLを保護してから通常のメモを区切り、クエリ内のカンマ等でURLが別商品へ分裂するのを防ぎます。URLを含む追加は生成AI補完へ送らず、名前未取得の項目を`/api/link-preview`の対象にします。元のURLは保持し、取得後も商品ページへのリンクとして表示します。URL文字列やドメイン名だけを品名にしていた旧記録も、保存URLがあれば同じ判定で補完します。

サーバーの`lib/server-link-preview.ts`は、Amazon、楽天市場、Yahoo!ショッピング、無印良品、ユニクロ、ニトリ、ヨドバシ、ビックカメラ、IKEA、ロフト、ZOZOTOWN、Qoo10、コストコ、Apple、Google ストア、メルカリ、SUIT SQUARE、UNITED ARROWSの18サイト群に属する指定ホストだけを取得します。追加したSUIT SQUAREは`uktsc.com`・`www.uktsc.com`、UNITED ARROWSは`store.united-arrows.co.jp`を対象とします。両ブランドも商品名のmeta情報またはタイトルを取得できる場合に限り、アクセス制限や商品名を含む情報がない場合は行内の手入力へ戻します。HTTPS、認証情報を含まないURL、許可したポートを条件とし、リダイレクト先も毎回同じ指定ホスト一覧で検査します。任意サイトをクロールする機能ではありません。

取得は8秒、リダイレクト3回、HTMLの先頭512KiBまでに制限します。HTMLをスクリプトとして実行せず、`og:title`、`twitter:title`、`title`から文字列を読み取り、既知の店名やアクセス拒否・ログイン等の一般タイトルを整理します。商品仕様・価格・在庫の取得や、タイトルが必ず実商品名に一致する保証は含みません。取得不能時は一覧の行内で名前を入力できます。補完待ちに本人が付けた品名は上書きしない条件をコードに置いています。

URL登録、対応サイトからの取得、失敗時の手入力と遅延時の操作は、変更後のブラウザ検証で確認します。コードやテストの存在だけで本番全サイトの取得成功とは表記しません。

## 端末保存・オフライン・PWA

`localStorage`はAIや通信を待たずに記録・未同期状態・revisionを端末へ保持します。認証後は`/api/state`が返すownerごとのキーを使い、匿名下書きとは分けます。匿名下書きは確認画面で採用するまで送信せず、APIも送信側ownerと現在の認証IDの一致を確認します。オフラインで開き直した場合はlast-ownerに対応する端末キャッシュを復元し、再接続時はGETで現在の認証ownerを確認した後に同期します。前のアカウントの記録を別ownerへ自動送信しません。アカウント切替や通信断の個別条件ごとの合否は検証記録で示します。

`public/sw.js`は画面シェルと静的アセットをキャッシュし、API・認証経路を除外します。PWA manifestは名前、アイコン、ホーム画面起動、共有先を宣言します。Service Workerの登録条件はHTTPSです。manifestの宣言だけで全ブラウザのホーム画面追加・共有ターゲットを確認済みとは扱いません。

ブラウザのデータ削除、端末変更、容量不足で端末内の記録は失われ得るため、同期状態の表示とJSONバックアップを用意します。localStorage自体を永続バックアップとは扱いません。

## 認証と公開状態

- サイトはprivateを既定とし、ユーザーごとにD1とR2を分離します。

- localhostの模擬ログインはループバック限定で、本番ビルドには含めません。ビルド済みWorkerのローカルAPI検証は、テスト用ヘッダーでユーザー分離を確認する別の検証です。
- GitHubへ買い物本文、Secret、端末データ、ローカルDB、ビルド・検証出力をコミットしません。
- 公開サイトは[買い物](https://mappei-shopping.feyfairy2048.chatgpt.site)、ソースは[GitHub](https://github.com/rimpeiota/mappei-shopping)です。本人確認は完了し、本番画面で2商品の追加、同期済み表示、再読み込み後の復元を確認済みです。この確認を他の全機能の合格へ拡大しません。

## 未接続・未確認の範囲

家族の権限・リアルタイム共有、通知配信、レシート・画像OCR、通販・店舗の価格取得・定期監視、位置通知、既存ノートとの自動双方向同期は未接続または未確認です。Workers AIは直接APIと公開済みアプリの接続確認ボタン経由で成功を確認済みですが、任意の自然文や全端末での解析精度を保証するものではありません。欄・URL・添付・推定表示があることと、外部連携が動くことを区別します。機能要望85項目をすべて実装・検証済みとは表記しません。

## 依存と検証の記録

表はアプリの利用技術とビルド・検証の道具です。スターターの`components/ui/`に含まれる未使用ライブラリを、本アプリの採用技術や完成機能として列挙しません。直接依存は`package.json`、全推移依存と固定バージョンは`package-lock.json`が正本です。

起動・SQL適用・テストのコマンドは[README](../README.md)を参照してください。構成とコマンドの存在は検証済みの証拠ではありません。実行環境・操作・合否・未確認事項は検証記録へ残します。

# 技術構成

更新日：2026-10-25。`package.json`、`package-lock.json`、画面・APIのimportと処理から記録しています。導入、実際の利用、外部接続の確認を区別します。

## 全体の流れ

```text
文字入力 / ブラウザの音声入力
  → 端末で即時解析・記録
  → localStorageの下書き
  → Cloudflare Workersの認証済みAPI
      ├ D1：ユーザー別の状態スナップショット
      ├ R2：ユーザー別の添付
      └ Workers AI：商品・数量・分類の整理（直接API・本番接続確認とも成功）
```

AIや通信の完了を入力の前提にしません。既存のローカルノートは自動取得しておらず、明示的な取り込み・書き出しでつなぎます。

`shopping_snapshots`はユーザーIDを主キーとし、更新は`WHERE user_id = ? AND revision = ?`を条件とする一つのSQLで実行します。競合時はHTTP 409とクラウドの状態を返します。PUTのownerと認証IDの不一致は拒否します。

添付はユーザーIDのSHA-256値とランダムUUIDでR2のキーを分離し、取得時も現在の認証IDからキーを組み立てます。配信には`nosniff`、private/no-store、制限したCSPを設定します。添付の保存はOCRの実装を意味しません。

## AIと音声入力

Workers AIのモデルは`@cf/meta/llama-3.1-8b-instruct`です。商品名・数量・単位・分類をJSONへ整理し、結果の形・数量・文字数・分類を検証します。入力文はデータとして渡し、文中の命令をアプリの指示へ昇格させません。

`AI` bindingがあれば`env.AI.run`、なければ`CLOUDFLARE_ACCOUNT_ID`と`CLOUDFLARE_AI_TOKEN`を使うHTTP REST APIを呼びます。SecretはWorker側だけで読みます。12秒で待機を打ち切り、未設定・通信失敗・形式不正の場合は通常の文字解析へ戻します。[Cloudflare公式のREST API手順](https://developers.cloudflare.com/workers-ai/get-started/rest-api/)

本人の明示承認を受け、Workers AIの読み取り権限に限定したAPIトークンを作成し、Sitesの秘密設定へ接続情報を登録済みです。直接REST APIでHTTP 200・成功応答を確認し、「牛乳2本、卵1パック」の商品・数量解析が成功しています。公開済みアプリの設定画面には「AI接続を確認」ボタンを追加済みで、実Chromeで「Workers AIの応答を確認しました」の成功表示を確認しています。接続確認の成功と、あらゆる自然文の解析精度は別に評価します。任意の購入先が`store: null`で返る場合は未指定として省略し、数量・分類などの検証は厳密なまま維持しています。トークン値やアカウント識別子は本資料・ソースへ記載しません。AIへ送るのは、その操作で入力したメモです。既存ノート全体や音声ファイルを自動送信するコードはありません。

音声入力はWeb Speech APIの`SpeechRecognition`または`webkitSpeechRecognition`を使います。対応・マイク許可はブラウザに依存し、使えないときは文字入力・端末キーボードの音声入力を案内します。認識結果は入力欄へ入り、追加操作で記録します。音声認識の処理主体やネットワーク利用はブラウザ実装に依存し、Cloudflareの音声認識を実装したものではありません。

## 端末保存・オフライン・PWA

`localStorage`はAIや通信を待たずに記録・未同期状態・revisionを端末へ保持します。認証後は`/api/state`が返すownerごとのキーを使い、匿名下書きとは分けます。匿名下書きは確認画面で採用するまで送信せず、APIも送信側ownerと現在の認証IDの一致を確認します。オフラインで開き直した場合はlast-ownerに対応する端末キャッシュを復元し、再接続時はGETで現在の認証ownerを確認した後に同期します。前のアカウントの記録を別ownerへ自動送信しません。アカウント切替や通信断の個別条件ごとの合否は検証記録で示します。

`public/sw.js`は画面シェルと静的アセットをキャッシュし、API・認証経路を除外します。PWA manifestは名前、アイコン、ホーム画面起動、共有先を宣言します。Service Workerの登録条件はHTTPSです。manifestの宣言だけで全ブラウザのホーム画面追加・共有ターゲットを確認済みとは扱いません。

ブラウザのデータ削除、端末変更、容量不足で端末内の記録は失われ得るため、同期状態の表示とJSONバックアップを用意します。localStorage自体を永続バックアップとは扱いません。

## 認証と公開状態

- サイトはprivateを既定とし、ユーザーごとにD1とR2を分離します。
- 本番のログイン、コールバック、IDヘッダー注入はSitesのdispatchが担当します。認証ヘッダーを信頼できるdispatch配下で動かす構成です。
- localhostの模擬ログインはループバック限定で、本番ビルドには含めません。ビルド済みWorkerのローカルAPI検証は、テスト用ヘッダーでユーザー分離を確認する別の検証です。
- GitHubへ買い物本文、Secret、端末データ、ローカルDB、ビルド・検証出力をコミットしません。
- 公開サイトは[買い物](https://mappei-shopping.feyfairy2048.chatgpt.site)、ソースは[GitHub](https://github.com/rimpeiota/mappei-shopping)です。本人確認は完了し、本番画面で2商品の追加、同期済み表示、再読み込み後の復元を確認済みです。この確認を他の全機能の合格へ拡大しません。

## 未接続・未確認の範囲

家族の権限・リアルタイム共有、通知配信、レシート・画像OCR、通販・店舗の価格取得・定期監視、位置通知、既存ノートとの自動双方向同期は未接続または未確認です。Workers AIは直接APIと公開済みアプリの接続確認ボタン経由で成功を確認済みですが、任意の自然文や全端末での解析精度を保証するものではありません。欄・URL・添付・推定表示があることと、外部連携が動くことを区別します。機能要望85項目をすべて実装・検証済みとは表記しません。
